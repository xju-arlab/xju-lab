## F02：拆分前端结构与演示状态

**依赖**：F01 的可运行基线。**目标**：后续每轮只改对应页面，避免继续扩张单文件。

- 将 Shell、公共组件、各页面分别移到 `components/layout`、`components/common`、`features/*`、`pages/*`。
- 路由独立到 `router.tsx`；统一演示状态移到单独 Provider/store；数据与类型保留清晰边界。
- 将模拟读写隔离到 `api/mock` 或可替换的数据层；初期不强制引入所有目标依赖。
- 项目/任务/请假/打印等修改在切换路由时保持；刷新统一重置，页面提示与实现一致。
- 不改变 F01 的外观和行为；顺便移除无用 imports，格式化长行；不要无关升级包版本。

**通过条件**：构建通过，路由切换和已有交互回归通过，状态保留口径清楚，`App.tsx` 只负责组合。

## F05：请假与审批交互

- 我的申请、申请表、详情、撤回、模拟教师审批；演示角色标签常驻，不形成真实授权误解。
- 校验起止、空白原因、重复提交；明确当前演示日期区间左闭右开。
- 原型内补充重叠提示与结果态；真实规则待 Q03 确认，正式版另有服务端约束。
- 审批先确认再操作，已处理申请不可再次决定；拒绝理由有输入入口。

**通过条件**：提交→待审批→模拟决定/撤回可复现，非法区间不能提交，导航后状态保留；不发送邮件。

## F06：PDF 与模拟打印队列

- 完成文件选择/拖入/替换/清空、类型/大小提示、选项、提交确认和队列取消。
- 若本轮加入 PDF 预览，优先适配飞跃 PdfViewer，确保对象 URL 释放；否则清楚显示“尚不预览”。
- 支持页码时必须解析总页数并验证；未实现时不展示虚假的页数/费用。
- 双面与彩色选项来自演示能力对象；未知/不支持时不可选。
- 模拟排队/完成/失败须明确标注，不真实上传或调用 CUPS；控制按钮只能影响模拟任务。

**通过条件**：非法文件拒绝，选项与记录一致，取消只作用当前任务；刷新/离线提示不误导用户。

## F07：监控与考核视图

- GPU 数量与空闲数从数组计算（当前应为总数 16、空闲 9、使用中 7）；不要硬编码汇总。
- 资源列表同时支持 GPU 节点与 CPU 部署节点；未知的 CPU 型号、核心数、内存和磁盘显示待录入，未接入监控前不显示虚构利用率。
- 图表保持示例标识；时间范围确有不同数据或说明为示意；补“未知/过期/采集失败”演示状态。
- 成长与考核固定两个 Tab：ACM 算法、深度学习理论基础；参考 OJ 排行榜和机试成绩表，继续使用飞跃组件。
- 两方向统一提供“本次排名 / 历史排名”。本次只按本场结果，历史按 25% / 75% 综合分；共享切换控件和历史榜列结构。
- ACM 以老成员标记过滤并重新计算当次和每场历史名次；归一化为 0–100 排名分后合成，支持个人明细与导出。新增“导入成绩”弹窗，仅需一个 OJ 比赛/排行榜链接；原型校验链接，未接入时明确不导入。
- 理论每场为笔试或机试之一，显示唯一的本场形式，支持成绩录入；同一培养期此前两类考试仍合并取均分，占 25%，当次占 75%。缺考、待评分、免考与有效 0 分分开，无历史采用当次分并标注首场。
- 演示成绩和成员分组存本浏览器，真实成绩和权限待 API 接入。具体规则及计分测试见[专项设计](../design/09-assessment-and-showcase.md)。

**通过条件**：监控卡片与总览口径一致；两个方向均有本次/历史两榜且排序正确，单场考试类型互斥，链接校验与未接入状态真实；过滤后当次及历史都重算，跨期/未来记录不混入，成绩录入和刷新保存可验证；窄屏只有表格横向滚动，页面不溢出。考核专项已实现并验证，监控专项仍按原计划继续验收。
