# 01 需求、范围与业务口径

[返回概要计划](README.md) · [验收与追踪](../acceptance.md)

## 1. 用户与使用范围

首版假设为单实验室、多房间，中文界面；业务时区建议 `Asia/Shanghai`，不随开发者电脑时区改变。成员规模暂按 100 人、50 并发会话、10 台打印机、30 台服务器规划，这些是容量测试基线，不是用户提供的真实规模。

| 身份 | 日常任务 |
|---|---|
| 访客 GUEST | 浏览已发布公开介绍、成果、新闻和招新信息 |
| 成员 MEMBER | 看工位、更新本人资料、请假、打印、参与项目会议、查看授权范围内的考核成绩与历史 |
| 教师 TEACHER | 看授权团队进展，审批指定成员请假，评阅所带成员考核 |
| 实验室管理员 LAB_ADMIN | 管理成员准入、工位、设备、内容和审批转交 |
| 实验室超级管理员 SUPER_ADMIN | 管理 LabOS 角色、身份配置及关键运维参数；授予此角色时同步同一账号的 OJ 管理员授权 |

GUEST 是匿名能力集合，不创建“共享游客账号”。实验室超级管理员身份不等于 Authentik 管理员；其 OJ 管理员联动是用户新增的明确需求，见[同步计划](../design/11-oj-import-and-admin-sync.md)。其他角色职责及完整对象权限矩阵尚待后端阶段冻结。

## 3. 首版边界

- 项目管理采用列表、轻量看板和可选甘特图；不做工时、复杂审批流、Git 自动同步。
- 打印仅接收 PDF，不在线转换 Office，不实现无硬件支持的自动双面；人工翻纸流程后置。
- 配额预留账本与估算字段，首版默认只统计、不收费、不默认执行“500 页/月”。
- 服务器只读监控，不进行 SSH 执行、进程管理、作业调度、GPU 预约和远程关机。
- 考核按已评分数据计算综合分与排名；不自动批改试卷、不自动作出培养资格决定，不从工位/请假推算考勤率。排名归一化、缺失值和首场回退见[考核详细设计](../design/09-assessment-and-showcase.md)。
- 公开展示先提供内容编辑和发布；招新先展示联系方式/说明，报名表与个人资料收集另立需求。
- PWA 支持安装及离线提示；内部数据、审批、打印操作要求在线，不提供离线提交队列。
- 不在 LabOS 创建密码、注册/找回密码流程；这些入口归 Authentik。

## 4. 统一业务口径

| 概念 | 本设计定义 |
|---|---|
| 工位已分配 | 当前存在有效分配关系，不证明成员到场 |
| 请假中 | `APPROVED` 且 `startAt <= now < endAt`；仅显示状态，不向全员公开原因 |
| 空闲工位 | 可用、非维护、当前无分配；临时工位另有类型标识 |
| 项目进度 | 完成的必需里程碑数 / 必需里程碑总数；零分母显示“未设置”，任务进度另列 |
| 我的待办 | 当前用户负责且未结束的统一任务记录，不重复计算会议与项目关联 |
| 打印页数 | 去重后的选中 PDF 页数 × 份数，属于逻辑打印面数；纸张数单独估算 |
| 打印成功 | CUPS/IPP 报告 completed；标注观测来源，不承诺每张纸已人工核验 |
| 设备在线 | 最近一次有效心跳/采集仍在阈值内；缺数据与离线分开 |
| 公开项目 | 明确发布的脱敏快照；项目设置“实验室可见”不意味着公开互联网可见 |

## 5. 质量目标（建议验收值）

在约定数据规模和部署环境记录下，普通列表 API p95 ≤ 500 ms，总览 API p95 ≤ 1 s；外部 OIDC、SMTP、文件传输和监控查询单列统计。首屏在约定测试网络下 p75 LCP ≤ 2.5 s，目标需在 A0 确认设备和网络后冻结。

内部页面以 375、768、1440 px 宽度验收；主操作支持键盘，颜色同时配文字/图标；关键文字以 WCAG AA 对比度为目标，继承飞跃的浅灰辅助文字也需复核，不能原样视作已达标。

数据恢复建议目标 RPO 24 h、RTO 4 h；通过一次实际恢复演练证明。外部服务故障时保留核心数据，不把 SMTP 接受当邮件已送达，不把缓存旧值伪装成实时值。
