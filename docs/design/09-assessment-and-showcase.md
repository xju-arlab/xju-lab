## 1. 页面与边界

`/app/assessment` 固定先显示 **ACM 算法**，第二个 Tab 为 **深度学习理论基础**（`?tab=theory`）。沿用飞跃的 Tailwind token、shadcn/Radix 弹窗和统一下拉组件，不引入第二套组件库。

- 两个方向统一使用“本次排名 / 历史排名”，默认本次；历史排名为截至所选场次的 25% / 75% 综合排行，切换方向保留视图选择。
- ACM：选择比赛、过滤老成员、维护成员标记；本次榜展示逐题结果，历史榜展示归一化分、历史均值与综合分；支持搜索、历史明细、CSV 导出和粘贴 OJ 链接的导入弹窗。实际导入待后端接入。
- 理论基础：每场只能是笔试或机试，本场形式由所选场次固定显示；本次榜仅按本场成绩排名，显示本场分项；历史榜显示本次名次、成绩、历史平均、有效场数和综合分。可直接录入总分或按分项加权，保留状态、评语及明细。
- 当前全部为虚构演示成员和成绩，带 `DEMO-` 编号；不代表参考站点的真实成绩，不连接 OJ 或评分服务。成绩修改和成员标记仅存本浏览器。
- 本模块统计已评分结果，不自动批改试卷、判题，也不自动决定录取、淘汰或其他培养资格。

## 2. ACM：先归一化，再按 25% / 75% 合成

### 2.1 当次排名与老成员过滤

成员具有明确的 `veteran` 标记，不从年级、学号或用户名猜测。开启过滤时，**先剔除老成员，再为当次和每一场历史比赛独立计算排名及有效参赛人数 N**。关闭时使用全部已关联参赛成员。姓名搜索只缩小展示范围，不改变 N、排名和积分。

ACM 原始成绩按通过题数降序、罚时升序排列；同通过数且同罚时为并列，显示竞赛排名（1、1、3）。展示题目通过情况、错误次数、通过时间与首解标识；首解来自源比赛事实，过滤后不把另一人的通过伪称为原比赛首解。原型罚时单位为秒，页面换算显示分钟。

### 2.2 百分位排名分

人数不同的比赛不直接平均名次。对某场过滤后共 N 位参赛者，将占位名次 r 换算为：

```text
N > 1：P = 100 × (N − r) / (N − 1)
N = 1：P = 50（没有相对比较证据）
N = 0：无有效排名分
```

并列者的 r 取并列组占据位置的均值。例如两人并列第一，r = (1 + 2) / 2 = 1.5；三人都零题且零罚时，则 r = 2、P = 50，而非人人获得 100 分。显示排名仍为 1、1、1。0 AC 但有正式参赛记录是有效成绩；没有参赛记录则不补造一条零分记录。

此分值表达同场相对位置，不测量跨场题目难度或绝对能力。10 人中第 2 名为 88.89；20 人中第 4 名为 84.21；每场有效排名分在历史均值中等权。不同人数下，接近的相对位置可比较，原始名次和 N 仍在明细保留。

### 2.3 历史与综合排行

```text
H = 同一培养期、早于所选比赛的本人有效排名分算术均值
C = 0.25 × H + 0.75 × P_current
```

例如历史均值 80，当次 90，综合分为 87.50，按综合分降序排列。未参赛不自动按 0 分处理，并展示本人有效历史场数/可用历史总场数。无历史时采用当次分作为综合分，标记“首场”；当次未参赛则不产生综合分或名次，只展示历史。

所有中间值保留完整精度，仅展示时保留两位小数。综合同分共享名次；原型以 1e-9 容差处理浮点误差，学号仅用于同分组内稳定显示，不作为打破平局的依据。

## 3. 深度学习理论基础

### 3.1 场次与成绩

每场标记培养期、名称、日期、单一类型（笔试或机试，互斥）和评分项。`kind` 必填且只能为 `written` 或 `practical`；不能同场选两类，也不允许学生自行切换场次形式。前端不再提供容易与场次类型设置混淆的“全部/笔试/机试”按钮，改为只读本场形式。每次最终成绩均在 0–100 内；已评分的 0 分有效，不与空值混淆。每人每场最多一条有效成绩，可修订但正式系统必须保留修订历史。

| 状态 | score | 参与历史均分 | 当次参与综合排名 |
|---|---|---|---|
| 已评分 graded | 有限数，0–100 | 是 | 是 |
| 待评分 pending | null | 否 | 否 |
| 缺考 absent | null | 否 | 否 |
| 免考 exempt | null | 否 | 否 |
| 无记录 | 无 | 否 | 否 |

缺考不自动记零是原型建议；正式缺考处罚及最低参赛次数需另确认，不能通过隐藏零分或默认补零暗中改变规则。

### 3.2 已确认的合并口径

```text
H = 同一培养期、早于所选场次的本人有效笔试和机试成绩的算术均值
C = 0.25 × H + 0.75 × S_current
```

笔试与机试合并，每场等权；先对所有历史场次取均值，不先分别求两类均值再平均。示例：此前笔试 80、机试 90，当次笔试 92，则 H = 85、C = 90.25。切换场次决定本场唯一类型，不改变跨类型的历史合并规则。当前场次及未来场次绝不重复计入 H，其他培养期也不计入。

本次排名使用独立的 `currentRank`，只由本场成绩计算；历史排名使用 `overallRank`，由综合分计算。例如 A 历史 100、本次 80，B 历史 0、本次 90，则本次 B 第一、A 第二，历史综合 A 为 85 分排第一、B 为 67.5 分排第二。同分共享名次，无本场有效分数不参加任一排名。

无历史、无当次、显示精度及同分规则与 ACM 相同。编辑较早场次后，原型会重新计算之后场次的均分；选择较早场次时只看到当时之前的历史。

### 3.3 分项分数与参考页面

参考 [dl.icthub.top](https://dl.icthub.top/) 的排名、学生、分项、总分和明细结构，以及 [2026Sep19CodingTest](https://gitcode.com/xju-arlab/2026Sep19CodingTest) 的机试背景。原型机试采用页面参考比例：Q2 代码/可视化、Q3 代码/可视化各 10%，提交速度 40%，提交规范 20%。每项以 0–100 录入，再按权重求当次总分。这是**当次试卷内部分项比例**，与跨场次的 25% / 75% 是两层独立计算。

笔试“概念理解 40%、推导计算 35%、分析应用 25%”仅为可替换的演示量规，不是用户已确认的正式试卷规则。直接录入总分时不伪造分项；切换为总分保存后清除原有分项，避免分项和总分矛盾。空值、非有限数、越界值和不完整分项不能保存。

提供的《科研实践招新与培养计划(5).pdf》用于培养主题和考核背景参考；其中整体培养评价比例不替代用户当前明确要求的历史 25% / 当次 75%。

## 5. 后端接入建议（尚未实现）

链接导入、单一考试类型的数据库约束，以及设置实验室超级管理员后同步 OJ 管理员的完整计划见 [11 OJ 导入与管理员同步](11-oj-import-and-admin-sync.md)。本节计分规则与该专项共同作为后端实施输入。

| 接口占位 | 目的 |
|---|---|
| `GET /api/v1/assessment/acm/contests` | 培养期内场次及同步状态 |
| `GET /api/v1/assessment/acm/contests/{contestId}/ranking` | 原始与历史综合排行，含过滤口径及版本 |
| `GET /api/v1/assessment/theory/exams` | 考试、类型、评分量规 |
| `GET /api/v1/assessment/theory/exams/{examId}/ranking` | 当次、历史明细和综合结果 |
| `PUT /api/v1/assessment/theory/exams/{examId}/grades/{memberId}` | 授权教师/管理员录入和修订 |
| `PATCH /api/v1/assessment/member-groups/{memberId}` | 按培养期维护成员分组 |
| `POST /api/v1/assessment/acm/imports`、`GET /api/v1/assessment/acm/imports/{importId}` | 管理员只粘贴比赛链接，服务端全量导入和查询任务状态 |

正式接口需包含 `termId`、事件开始时间与顺序、源数据版本、算法版本、过滤参数和计算时间。原型用日期比较且每天一场；正式同一天多场必须用带时区时间戳/明确序号排序，不能按页面顺序或标题猜测先后。

建议实体为 TrainingTerm、TermMember（老成员标记）、ContestSnapshot、ContestResult、Exam、RubricSnapshot、GradeRevision、RankingSnapshot。稳定成员 ID 与 OJ user ID 显式关联，不只按昵称连接；未关联、重复账号、封榜、未结束场次、同步失败及不完整数据单独显示。默认仅完整的已结束比赛用于正式综合排行。OJ 只读同步必须拿齐整场分页后计算 N，不能把当前页当作全部参赛者；无权访问时显示未接入，不绕过权限。

正式排名由服务端重新计算，前端结果不能作为写入的权威分数。修改成员标记应对该培养期当次及历史各场统一重算，并产生可追溯新版本；已发布快照不被静默改写。成绩修订保留操作者、前后值、原因、时间和乐观锁版本。量规修改不覆盖历史试卷快照。权限需区分本人查看、授权团队查看、录入、成员分组与发布，并由服务端执行。
